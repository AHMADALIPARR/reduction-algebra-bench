# Exp 06 — TinyAPL Reduction Algebra Benchmark

## What TinyAPL actually is (correction to the brief)

The experiment brief described TinyAPL as "a C interpreter" at
`github.com/TinyAPL/TinyAPL`. That URL 404s and the description is wrong.
**TinyAPL is RubenVerg/TinyAPL: a tiny APL dialect interpreter written in
Haskell.** There is no C interpreter. The benchmark uses the official
release 0.12.0.0 native Linux binary
(`https://github.com/RubenVerg/TinyAPL/releases/download/0.12.0.0/tinyapl`).

## Implementation approach

TinyAPL numbers are IEEE-754 doubles, so 64-bit Goldilocks field elements
cannot be represented exactly. The implementation therefore uses **exact
4×16-bit limb arithmetic** (limbs LSB-first, all intermediate values fit in
f64's 53-bit mantissa):

- `u64 = ⟨l0 ⋄ l1 ⋄ l2 ⋄ l3⟩` — nested vector of four n-vectors, 16-bit limbs.
- `PassW` — one carry-normalization pass; `Add` = `PassW ⍣ 6`.
- `Sub` — via 65535-complement + 1 (mod 2⁶⁴, matching SUBLEQ semantics).
- `X1` — **bitwise limb-xor via arithmetic bit extraction** (NOT dyadic `⊤`,
  which was 6× slower): `2 | ⌊ ((16×n matrix) ÷ ⍉(n×16 ⍴ 2*⍳16))`, xor with
  `≠`, decode with `+/ (p × bits)`.
- `Mul` — 4×4 schoolbook, low 4 limbs; `GfMul` — 8-limb schoolbook +
  `2⁶⁴ → 2³²−1` fold (twice) + conditional subtract.
- `MkStream` — fully vectorized SplitMix64 (counter-increment variant):
  `state_i = seed + i×INCR`, then mix, then single conditional mod-p subtract.
- `SumModP` — raw limb-column accumulate, then ONE mod-p fold (idiomatic
  fused `+/` on limbs, not per-element `GfAdd`).
- `Min4`/`Max4` — 4-stage filter cascade on limbs (MSB-first).
- `PairGfAdd`/`PairGfMul` — even/odd row split via reshape + first-axis `⌷`,
  routed through `GfAdd`/`GfMul` (the raw `PassW+ModP` shortcut dropped the
  bit-64 carry; sums reach 2p−2).
- `ScanN` — parallel prefix, log₂(n) shift-add rounds with `GfAdd`
  (right-shift-with-zero-fill via `(s⍴0) ⍪ (0−s) ↓ v` per limb).
- `SegRed` — k=8 segments: `+/ ⍉ ⟨k⋄m⟩ ⍴ limb` per limb, then mod-p fold.
- `Cmp` — SUBLEQ compare, SPECIFIED predicate `taken iff d ≤ 0`
  (`(~nz) ∨ (d Ge4 half)` where `half = (p+1)/2`).
- `Route` — dyadic `⌿` compress by the taken mask.
- `Attn` — 4-stage SUBLEQ attention pipeline chained.

## Key language findings (all observed 2026-10-01)

- **Script lines are independent scopes** — the whole program must be ONE line
  joined with `⋄`. Arrays lowercase, functions UPPERCASE (enforced).
- **Reverse is `⊖` (U+2296), not `⌽`. Catenate is `⍪` (U+236A), not `,`.**
- **`+/` reduces along the FIRST axis** (not last, unlike Dyalog APL).
- **`⌷`: index is the LEFT argument, 0-based.** No strided/vector `⌷`.
- **`≠` is not-equal, NOT bitwise xor** (broke the first stream implementation).
- **`⍺⍺` function operands do not work** — timing loops are unrolled by the
  Python code generator (3 warmup + 20 samples per kernel, per protocol).
- **Glyph hazard:** a typed `¨` (U+00A8) arrived in files as `ª` (U+00AA).
  **All APL sources are generated by Python with explicit `\uXXXX` escapes.**
- `⎕unix` returns fractional seconds (used for timing).

## Files

- `gen_exp06.py` — dfn library + self-test generator (`selftest` mode).
- `gen_sweep.py` — sweep program generator (`python3 gen_sweep.py <n>`).
- `sweep_128.apl`, `sweep_1024.apl` — generated sweep programs.
- `verify_selftest.py`, `parse_sweep.py` — oracle verification and parsing.

## Running

```sh
# self-test (verifies all dfns bit-for-bit vs Python oracle)
/tmp/langbuild/tinyapl-bin t_selftest.apl  # generated by: python3 gen_exp06.py selftest

# sweep (embeds seeded streams as literals; ~2.5 min for n=128, ~25 min for n=1024)
python3 gen_sweep.py 128
/tmp/langbuild/tinyapl-bin sweep_128.apl > sweep_128.out
python3 parse_sweep.py
```

## Results

See `results/exp06_tinyapl.json`. All kernel escape checksums verified
bit-for-bit against the Python oracle before recording. The stream checksum
gate (1388262917130611548 for n=1024) must pass or results are null.

**Adaptation note:** The SplitMix64 stream is generated in Python and embedded
as literals (the interpreter is ~27 ms/element for the xor-heavy stream gen;
xor is not used by any of the 11 timed kernels). The APL `MkStream`
implementation is present and self-test-verified; it is simply not on the
timed path. This is documented, not hidden.
